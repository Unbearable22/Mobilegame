# Android touch: версия 0.2.0

## Что подтверждено

Пользователь сообщил о неработающих поворотах на настоящем телефоне. В доступном окружении телефон не подключён. Исходный сбой именно этого устройства **не воспроизведён**: native `Input.parse_input_event(ScreenTouch)` в Godot 4.7.2 под Xvfb доходит до старого touch-обработчика и поворачивает узел. Поэтому окончательная причина телефонного случая остаётся непроверенной.

В старом обработчике подтверждена хрупкая зависимость: GUI MouseButton отбрасывался по глобальному `Input.is_emulating_touch_from_mouse()`. Этот флаг не определяет происхождение отдельного события. Обычные Android Control-кнопки используют GUI mouse-route; если поле получает такой маршрут без отдельного native GUI touch, старый guard исключает действие. Также простое отключение флага в старой реализации даёт двойной поворот: обрабатываются и эмулированный mouse, и native touch. Прямые вызовы `_gui_input` и push_input touch не проверяли всю эту цепочку.

## Исправленный маршрут

`emulate_mouse_from_touch=true`, `emulate_touch_from_mouse=false`. Поле выполняет действие только для GUI pressed left MouseButton. Godot переводит касание в этот же маршрут; native touch остаётся доступен для debug-журнала, но повторно не выполняет действие. Физическая мышь также работает. Нет таймерной дедупликации и нет зависимости от глобального флага происхождения события.

Координаты GUI уже локальные для Board. Центры и радиусы вычисляются в той же системе, hit-круг меньше половины клетки, области соседей не пересекаются. Поворот сохраняет прежнюю механику: один тап — 90° по часовой стрелке, четыре — исходное направление, `used` не меняется, Undo/Restart восстанавливают состояние. После первого запуска повороты запрещены; интерфейс сообщает правило и предлагает Restart/Undo. Для уровней без поворотных узлов сохраняются их обучающие подсказки.

## Диагностика на телефоне

1. Установить новый **debug APK 0.2.0**, открыть шестерёнку → «Диагностика: Вкл».
2. Подключить USB debugging. Выполнить `adb logcat -c`, затем `adb logcat -v time` и сохранить вывод во время попытки поворота уровня 3 или 9. Для просмотра только записей можно фильтровать по `[TouchDebug]` средствами терминала.
3. Закрыть настройки, до запуска коснуться стрелки с дугой. Затем запустить источник и повторить касание после реакции.
4. Передать модель телефона/Android, SHA256 APK, номер уровня, снимок и строки `[TouchDebug]`.

Записи:
- `native-touch`: факт получения ScreenTouch, позиция viewport, палец, текущий экран.
- `board-gui`: позиция Board и viewport, прямоугольник поля, размер клетки, индекс, device, locked и причина отказа.
- `action`: тип/индекс, разрешение поворота, реальные dirs до/после, accepted или причина отказа.

Godot может доставить эмулированный mouse до исходного GUI touch, поэтому action иногда записан раньше native-touch; это не двойное действие.

Если есть native-touch, но нет board-gui — проверять перекрытие/маршрутизацию/геометрию; если board-gui index=-1 — координаты/hit-test; если index правильный, но locked/reason — состояния; accepted с изменёнными dirs, но без видимого поворота — представление. Это локализация, а не доказательство исправления конкретного телефона.

Диагностика по умолчанию выключена, не сохраняется. В release не показывается, setter не позволяет включить её, журнал защищён `OS.is_debug_build()`. Оверлея поверх поля нет, журнал не перехватывает события.

## Выполненные проверки

51 проверка native/GUI-маршрутов в headless: четыре поворота, native/эмулированное нажатие по одному действию, Undo/Restart, normal/target/outside, source, busy/modal, directional/splitter, реальный маршрут энергии, запрет после запуска. Отдельный Xvfb-прогон в реальных окнах 720×1280, 1080×1920, 1440×3200 отправляет native Input-события на шестерёнку, CheckButton, Close и узел; все три процесса exit0. Реальная проверка на телефоне ожидает пользователя.
